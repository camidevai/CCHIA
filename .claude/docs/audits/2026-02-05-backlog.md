### C-02: `/release` permite bypass de `/qa --env qa`

**Área:** Skills (Flujos)
**Archivo:** `.claude/skills/release/SKILL.md` (líneas 131-179)
**Esfuerzo:** Medio (2-3 horas)

**Problema:**
El skill `/release` ofrece opción de continuar sin QA de integración aprobado, sin requerir flag `--force`.

**Evidencia:**
```bash

  echo "Opciones:"

**Impacto:**

**Solución propuesta:**

- QA env APPROVED es obligatorio para release
```

### C-04: Pre-check DETACHED_HEAD sin excepción para worktrees

**Área:** Validación
**Archivo:** `.claude/validation/pre-checks/git.md` (líneas 107-128)
**Esfuerzo:** Bajo (30 min)

**Problema:**
Pre-check emite WARNING para cualquier detached HEAD, pero qa/ y prod/ DEBEN usar detached HEAD por diseño.

**Evidencia:**
```typescript
if (!branch.trim()) {
  result.warnings.push('DETACHED_HEAD');  // SIN EXCEPCIÓN
}
```

**Solución propuesta:**
```typescript
const isWorktreeQaProd = cwd.includes('.worktrees/environments/qa') ||
                         cwd.includes('.worktrees/environments/prod');
if (!branch.trim() && !isWorktreeQaProd) {
  result.warnings.push('DETACHED_HEAD');
}
```

### H-04: Modificar Security Gate para detectar archivos nuevos

**Área:** Security
**Archivo:** `.claude/security/checks/secrets.md`
**Esfuerzo:** Medio (2 horas)

**Problema:**
`git diff --name-only` no muestra archivos nuevos untracked. Archivos con secrets pueden pasar el gate.

**Solución:**
```bash

  git diff --cached --name-only
  git diff --name-only HEAD~1
  git ls-files --others --exclude-standard
) | sort -u
```
